> **Адрес репозитория.** В командах ниже он обозначен как `$REPO_URL`. Перед установкой задайте его один раз — адрес берётся на странице репозитория (кнопка **Code → HTTPS**):
> ```bash
> REPO_URL=https://github.com/<аккаунт>/AmoCRM-MCP-for-GigaCowork.git
> ```
> Если репозиторий приватный или git недоступен — скачайте архив (**Code → Download ZIP**) и распакуйте в нужную папку вместо `git clone`.

## 1. Как это устроено

```
ИИ-платформа (GigaCowork, Claude, Cursor…)
        │  HTTPS + ключ доступа (MCP_AUTH_TOKEN)
        ▼
  amoCRM MCP-сервер   ← этот проект, на вашем сервере/хостинге
        │  HTTPS + долгосрочный токен amoCRM (AMOCRM_TOKEN)
        ▼
      amoCRM API v4
```

Два разных секрета:
- **`AMOCRM_TOKEN`** — доступ сервера к amoCRM. Его знает только сервер.
- **`MCP_AUTH_TOKEN`** — ключ, по которому ИИ-платформа подключается к серверу. Без него сервер отвечает 401.

## 2. Что понадобится

- Аккаунт amoCRM (или Kommo) и **права администратора** в нём.
- Место для сервера: VPS, виртуальный хостинг с Python или свой компьютер (см. раздел 4).
- Для работы через интернет — **домен или поддомен** (например, `mcp.company.ru`), он нужен для HTTPS.

## 3. Токен amoCRM

1. amoCRM → **amoМаркет** (иконка слева) → **«⋯»** справа вверху → **«Создать интеграцию»**.
2. Заполните форму:
   | Поле | Значение |
   |---|---|
   | Ссылка для перенаправления | адрес вашего сервера, например `https://mcp.company.ru` (подойдёт любой https-адрес) |
   | Ссылка для хука об отключении | пусто |
   | **Предоставить доступ: Все** | ✅ отметить |
   | Контроль дублей, Множественные источники | не отмечать |
   | Название | `MCP коннектор` |
   | Описание | любое |
3. **«Сохранить»** → откроется карточка интеграции (или amoМаркет → «Установленные» → «MCP коннектор»).
4. Вкладка **«Ключи и доступы»** → блок **«Долгосрочный токен»** → **«Сгенерировать токен»** → срок (до 5 лет) → **«Подтвердить»**.
5. **Сразу скопируйте токен** (длинная строка `eyJ…`): повторно его не покажут.

> Права сервера равны правам пользователя, выпустившего токен. Для полного доступа токен выпускает администратор.
> Токен не пересылайте в мессенджерах и чатах. Если это случилось, удалите его в карточке интеграции и выпустите новый.

## 4. Где разместить сервер: выбор варианта

| Вариант | Для чего | Сложность |
|---|---|---|
| **А. VPS + Docker** | боевая работа, любые платформы | ★★☆ |
| **Б. VPS без Docker** | если Docker нельзя поставить | ★★☆ |
| **В. Виртуальный хостинг** (ispmanager: Рег.ру, Beget, Timeweb…) | быстрый тест на уже оплаченном хостинге | ★★☆ |
| **Г. Локально** | Claude Desktop, Cursor на своём компьютере | ★☆☆ |

О размещении: через сервер проходят персональные данные клиентов из CRM (ФИО, телефоны, email). Для работы с данными граждан РФ обычно выбирают сервер в России (152-ФЗ). Уточните это у ответственного за данные.

Минимальные ресурсы: 1 vCPU, 512 МБ–1 ГБ RAM, 1 ГБ диска. Python 3.10+.

## 5. Вариант А: VPS с Docker (рекомендуется)

**5.1. Сервер и домен**
1. Арендуйте VPS с Ubuntu 22.04/24.04.
2. В DNS вашего домена добавьте **A-запись**: имя `mcp`, значение — IP сервера. Получится `mcp.company.ru`.

**5.2. Установка** (по SSH, от root или через sudo)
```bash
# Docker
curl -fsSL https://get.docker.com | sh

# Проект
git clone "$REPO_URL" /opt/amocrm-mcp
cd /opt/amocrm-mcp
cp .env.example .env
openssl rand -hex 32          # скопируйте результат — это MCP_AUTH_TOKEN
nano .env
```
В `.env` заполните:
```env
AMOCRM_DOMAIN=mycompany            # из адреса mycompany.amocrm.ru
AMOCRM_TOKEN=eyJ...                # токен из раздела 3
MCP_AUTH_TOKEN=<результат openssl>
PUBLIC_BASE_URL=https://mcp.company.ru
MCP_DOMAIN=mcp.company.ru
```
Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`) и запустите:
```bash
chmod 600 .env
docker compose --profile https up -d --build
```
Caddy сам получит HTTPS-сертификат Let's Encrypt (порты 80 и 443 должны быть свободны).

**Если на сервере уже есть nginx:** запускайте без Caddy (`docker compose up -d --build`; приложение слушает `127.0.0.1:8000`), а nginx настройте по примеру `deploy/nginx.conf`. Сертификат выпустите через `certbot --nginx -d mcp.company.ru`.

**Полезные команды**
```bash
docker compose logs -f amocrm-mcp     # журнал
docker compose restart amocrm-mcp     # перезапуск после правки .env
```

## 6. Вариант Б: VPS без Docker

```bash
apt update && apt install -y python3 python3-venv git nginx certbot python3-certbot-nginx
git clone "$REPO_URL" /opt/amocrm-mcp
cd /opt/amocrm-mcp
python3 -m venv venv && venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env && chmod 600 .env     # как в разделе 5.2
chown -R www-data /opt/amocrm-mcp

cp deploy/amocrm-mcp.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now amocrm-mcp

cp deploy/nginx.conf /etc/nginx/sites-available/amocrm-mcp   # замените server_name на свой домен
ln -s /etc/nginx/sites-available/amocrm-mcp /etc/nginx/sites-enabled/
certbot --nginx -d mcp.company.ru
systemctl reload nginx
```
Журнал: `journalctl -u amocrm-mcp -f`.

## 7. Вариант В: виртуальный хостинг (ispmanager, Рег.ру и др.)

Подходит для теста. Работает через Passenger (WSGI): доступен адрес `/mcp`, SSE недоступен. Проверено на Рег.ру (ispmanager 6).

**7.1. В панели хостинга**
1. **Сайты → Создать сайт:** имя — поддомен, например `mcp.company.ru`. Включите **«Защищённое соединение (SSL)»** и выберите сертификат **Let's Encrypt**. Если доступен только самоподписанный, выпустите Let's Encrypt в разделе «SSL-сертификаты».
2. Откройте настройки созданного сайта (двойной клик) → **«Дополнительные возможности»**: включите **«CGI-скрипты»**, затем **«Python»**, выберите **версию 3.12** (или 3.10+) → **«Сохранить»**.
3. Убедитесь, что поддомен указывает на IP хостинга. Обычно запись добавляется автоматически, проверить можно в «Управление DNS».

**7.2. В терминале хостинга** (SSH или «Shell-клиент» в панели)
```bash
cd ~
git clone "$REPO_URL" amocrm-mcp
cd amocrm-mcp
bash deploy/install_shared_hosting.sh mcp.company.ru
```
Скрипт:
- создаст окружение Python и установит библиотеки;
- создаст `.env` со случайным ключом доступа;
- положит в папку сайта загрузчик `passenger_wsgi.py`, а стандартные `index.html` и `.htaccess` переименует в `.bak`;
- перезапустит приложение и проверит `/health`.

Важно: версия Python в скрипте и в настройках сайта должна совпадать. Скрипт выбирает 3.12, если она есть. Другую можно указать вторым аргументом: `bash deploy/install_shared_hosting.sh mcp.company.ru /opt/python/python-3.11/bin/python3`.

**7.3. Токен amoCRM.** Откройте `~/amocrm-mcp/.env` (в панели: «Менеджер файлов» → `amocrm-mcp` → `.env` → «Изменить») и впишите:
```env
AMOCRM_DOMAIN=mycompany
AMOCRM_TOKEN=eyJ...
```
Сохраните и перезапустите: `touch ~/www/mcp.company.ru/.restart-app`.

**Если git на хостинге нет:** скачайте архив репозитория (GitHub → Code → Download ZIP), загрузите его через «Менеджер файлов» в домашнюю папку (не в `www`!), распакуйте в `~/amocrm-mcp` и продолжите с команды `bash deploy/install_shared_hosting.sh …`.

## 8. Вариант Г: локально на компьютере

Нужен Python 3.10+.
```bash
git clone "$REPO_URL" amocrm-mcp
cd amocrm-mcp
python3 -m venv venv && venv/bin/pip install -r requirements.txt
```
Claude Desktop (`claude_desktop_config.json`) или Cursor (`mcp.json`):
```json
{
  "mcpServers": {
    "amocrm": {
      "command": "/полный/путь/amocrm-mcp/venv/bin/python",
      "args": ["/полный/путь/amocrm-mcp/server.py", "stdio"],
      "env": { "AMOCRM_DOMAIN": "mycompany", "AMOCRM_TOKEN": "eyJ..." }
    }
  }
}
```
Windows: путь вида `C:\\amocrm-mcp\\venv\\Scripts\\python.exe`. Ключ `MCP_AUTH_TOKEN` в этом режиме не нужен.

## 9. Проверка работы

```bash
# 1. Сервер жив (без ключа): {"ok":true,"tools":50,...}
curl https://mcp.company.ru/health

# 1б. Глубокая проверка: токен amoCRM действует и журнал изменений доступен (200 / 503)
curl https://mcp.company.ru/health?deep=1

# 2. Без ключа доступ закрыт: 401
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://mcp.company.ru/mcp

# 3. С ключом: список инструментов (должно быть 48)
K=<MCP_AUTH_TOKEN>
curl -s https://mcp.company.ru/mcp -H "Authorization: Bearer $K" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | grep -o '"name":"[a-z_]*"' | wc -l

# 4. Связь с amoCRM: данные аккаунта
curl -s https://mcp.company.ru/mcp -H "Authorization: Bearer $K" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_account_info","arguments":{}}}'
```

## 10. Подключение к ИИ-платформе

Сервер принимает ключ четырьмя способами, выберите поддерживаемый платформой:

| Способ | Что указать |
|---|---|
| **Логин и пароль** (GigaCowork и др.) | Логин: любой, например `amocrm`. **Пароль: значение `MCP_AUTH_TOKEN`** |
| Заголовок Bearer | `Authorization: Bearer <MCP_AUTH_TOKEN>` |
| Заголовок X-API-Key | `X-API-Key: <MCP_AUTH_TOKEN>` |
| Ключ в адресе | `https://mcp.company.ru/mcp?key=<MCP_AUTH_TOKEN>` |

**Адрес сервера:** `https://mcp.company.ru/mcp` (Streamable HTTP). Для старых клиентов, где нужен SSE: `https://mcp.company.ru/sse` (только варианты А, Б и Г).

**GigaCowork, по шагам:**
1. Настройки → Управление расширениями → **Интеграции** → **«Добавить интеграцию»** → MCP-сервер.
2. Адрес: `https://mcp.company.ru/mcp`.
3. Способ авторизации — логин/пароль. При подключении в окне «Авторизация» введите логин `amocrm` и пароль = `MCP_AUTH_TOKEN`. **Не вводите** почту и пароль от amoCRM.
4. Включите интеграцию в нужном пространстве и задайте вопрос, например: «Покажи все сделки на этапе "Переговоры" в воронке "Продажи"».

Посмотреть ключ: `grep MCP_AUTH_TOKEN .env` в папке проекта.

## 11. Настройки (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `AMOCRM_DOMAIN` | да | `mycompany` (→ .amocrm.ru) или полный адрес `mycompany.amocrm.com` / `mycompany.kommo.com` |
| `AMOCRM_TOKEN` | да | долгосрочный токен (раздел 3) |
| `MCP_AUTH_TOKEN` | да (HTTP) | ключ доступа к серверу; несколько — через запятую (удобно для смены ключа без простоя) |
| `PUBLIC_BASE_URL` | для выгрузок | внешний адрес сервера, нужен для ссылок на XLSX/CSV |
| `AMOCRM_TIMEZONE` | нет | часовой пояс дат, по умолчанию `Europe/Moscow` |
| `MCP_READ_ONLY` | нет | `1` — только чтение: инструменты изменения отключены |
| `MCP_ALLOW_DESTRUCTIVE` | нет | `0` (по умолчанию) — удаление воронок, этапов, полей, вариантов списков и DELETE через произвольный запрос запрещены. Включайте временно и только при необходимости |
| `MCP_ALLOW_RAW_WRITE` | нет | `0` (по умолчанию) — произвольный запрос к API только на чтение |
| `MCP_CONFIRM_THRESHOLD` | нет | изменение больше стольких записей требует подтверждения (по умолчанию 10) |
| `MCP_MAX_WRITE_ITEMS` / `MCP_MAX_BULK_ITEMS` | нет | максимум записей за вызов / в массовом изменении (500 / 2000) |
| `MCP_AUDIT_DIR` | нет | папка журнала изменений (по умолчанию `audit/` в проекте; в Docker — `/data/audit`, том `data`) |
| `MCP_DEDUPE_MINUTES` | нет | окно защиты от повторного создания, минут (10) |
| `MCP_TOOLSETS` | нет | только нужные группы инструментов: `reference,leads,contacts,tasks,…` (меньше инструментов — проще модели) |
| `AMOCRM_RPS` | нет | запросов в секунду к amoCRM (лимит amoCRM — 7, по умолчанию 6) |
| `MCP_MAX_FETCH_ITEMS` | нет | максимум записей в выгрузке/отчёте (по умолчанию 50 000) |
| `EXPORT_TTL_HOURS` | нет | сколько часов хранятся файлы выгрузок (по умолчанию 24) |

После изменения `.env` перезапустите сервер: Docker — `docker compose restart`, systemd — `systemctl restart amocrm-mcp`, хостинг — `touch ~/www/<поддомен>/.restart-app`.

## 13. Безопасность

### Как сервер защищает данные клиента
- **Журнал изменений** (`MCP_AUDIT_DIR`): каждое изменение — с op_id, аргументами и значениями «до». Если журнал недоступен для записи, сервер отказывается что-либо менять. Журнал — это файлы `audit-ГГГГ-ММ.jsonl`, их стоит включить в резервное копирование.
- **Отмена**: попросите ИИ «отмени последнее изменение» или вызовите `undo_change(op_id)`; история — `get_change_log`.
- **Подтверждение**: крупные, массовые и необратимые операции выполняются только в два шага — сначала предпросмотр «было → станет», затем повтор с `confirm_token` после согласия пользователя.
- **Необратимые операции выключены** по умолчанию (`MCP_ALLOW_DESTRUCTIVE=0`). Через API amoCRM вообще нельзя удалить сделки, контакты и компании.
- **Без дублей**: создание не повторяется автоматически при сбоях связи; одинаковый повторный вызов в течение 10 минут ничего не создаёт.
- Для пользователей, которым не нужны изменения, запускайте отдельный экземпляр с `MCP_READ_ONLY=1`.

### Секреты и доступ

- `.env` никогда не коммитьте в git (он уже в `.gitignore`). Права на файл: `chmod 600 .env`.
- На хостинге код и `.env` держите **вне** папки сайта (`~/www/...`). В папке сайта должен лежать только загрузчик.
- Если ключ или токен попал в переписку или чужие руки:
  - **`MCP_AUTH_TOKEN`** — сгенерируйте новый (`openssl rand -hex 32`), замените в `.env`, перезапустите сервер и обновите ключ в платформе;
  - **`AMOCRM_TOKEN`** — удалите в карточке интеграции amoCRM и выпустите новый.
- Для пользователей, которым не нужны изменения в CRM, запускайте отдельный экземпляр с `MCP_READ_ONLY=1`.

## 14. Решение проблем

| Симптом | Причина и решение |
|---|---|
| Платформа пишет «MCP отклонил credentials» / 401 | Неверный ключ. Логин любой, **пароль = `MCP_AUTH_TOKEN`** целиком, без пробелов. Почта и пароль от amoCRM сюда не подходят |
| `/health` отдаёт заглушку хостинга или 404 | Python не включён для сайта (раздел 7.1, п. 2), в папке сайта остался `index.html` или нет `passenger_wsgi.py` |
| В журнале ошибок `PassengerPython not allowed here` | Удалите строку `PassengerPython` из `.htaccess` в папке сайта (а лучше сам `.htaccess`): версия Python задаётся в панели |
| «Web application could not be started» | Версия Python в панели не совпадает с версией окружения `venv`, или библиотеки не установлены. Пересоздайте окружение той же версией: `rm -rf venv && bash deploy/install_shared_hosting.sh <домен> /opt/python/python-3.X/bin/python3` |
| Ответ инструмента: «Токен amoCRM недействителен или истёк» | Выпустите новый долгосрочный токен (раздел 3), впишите в `.env`, перезапустите |
| «Сервер не настроен: задайте AMOCRM_DOMAIN и AMOCRM_TOKEN» | Не заполнен `.env` или сервер не перезапущен после правки |
| «Нет прав на это действие» (403) | Токен выпущен пользователем без нужных прав. Выпустите токен от администратора |
| Ошибка 429 / медленно на больших выборках | Сработал лимит amoCRM (7 запросов/с). Сервер сам делает паузы и повторы; для тысяч записей используйте `export_format` или отчёты |
| Ссылка на выгрузку не открывается | Задайте `PUBLIC_BASE_URL`; срок хранения файла — `EXPORT_TTL_HOURS` |
| Ответ «needs_confirmation» | Это не ошибка: изменение ещё не применено. Покажите предпросмотр пользователю и повторите вызов с `confirm_token` |
| «Журнал изменений недоступен… Изменения НЕ выполнены» | Нет прав на папку журнала. Проверьте `MCP_AUDIT_DIR` и права (`chmod 700`, владелец — пользователь сервера) |
| «…отключено настройками сервера (MCP_ALLOW_DESTRUCTIVE=0)» | Защита от необратимых операций. Если удаление действительно нужно — временно задайте `MCP_ALLOW_DESTRUCTIVE=1`, перезапустите, выполните, верните `0` |
| «Фильтр пустой…» | Массовое изменение без условий запрещено. Укажите воронку, этап, ответственного, даты или список ID |
| ok=false и failed_ids | Изменение применено частично (сбой amoCRM посреди пачки). Применённое можно отменить по op_id; оставшиеся повторите отдельно |
| Платформа не видит инструменты | Проверьте адрес: он должен заканчиваться на `/mcp`. Проверьте ответ `tools/list` командой из раздела 9 |

Журналы ошибок: Docker — `docker compose logs`, systemd — `journalctl -u amocrm-mcp`, хостинг Рег.ру — `~/logs/<поддомен>.error.log`.
